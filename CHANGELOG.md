# Changelog

## 1.0.0

First public release.

- **Panel.** A native macOS AppKit panel for omp usage: compact provider rings on either side of the camera (or one floating capsule below the menu bar), an expanded dashboard with per-provider and per-account detail, exact unknown / zero / over-limit states, an elapsed-period marker and warning / critical thresholds. A provider that omp stops reporting disappears after the next successful result; its saved selection and side are kept for reconnection. Panel placement can be pinned to a monitor and moved with Option-drag.
- **Collector.** A Node.js collector runs `omp usage --json`, normalizes it and keeps a per-profile cache with stale recovery (60-second poll and five-minute cache by default). It never reads omp credentials and needs no interactive omp session.
- **Settings.** One Settings window (Collection, Display, Providers, Labels, Metrics, Runtime, Updates) with staged edits applied by **Save & Apply**; the configuration is `~/Library/Application Support/omp-usage-panel/config.json`.
- **One-line install.** `curl -fsSL https://raw.githubusercontent.com/dhkimxx/omp-usage-panel/main/install.sh | sh` downloads the release DMG, verifies its size and SHA-256 against the digest GitHub publishes, mounts it read-only, installs the app headlessly (`OMPUsagePanel --install [--omp PATH] [--profile NAME]`) and unmounts. Files fetched by `curl` carry no quarantine attribute, so macOS's first-launch block does not appear. The DMG on the release page remains as a manual install with a native setup window. Both paths install to `~/Applications/OMP Usage.app` without admin rights, register a per-user login LaunchAgent, keep an existing valid `config.json` byte for byte and never overwrite an invalid one.
- **Bundled Node.js.** A pinned official Node.js 22.23.5 ships as `node-arm64.tar.xz` / `node-x64.tar.xz` (about 49 MB in total). Because a quarantined, unnotarized Node binary is killed by macOS when executed, it is never run inside the app bundle: on start the app extracts the verified binary for the machine's architecture (even under Rosetta) to `~/Library/Application Support/omp-usage-panel/runtime/node-<version>-<arch>/`, feeding the archive to `tar` through a pipe so quarantine is not inherited, checks the archive and binary against pinned SHA-256 values and Node.js's Developer ID team, excludes it from backups and runs the collector, setup helper and updater from it. Superseded runtimes are removed once no update is pending, and uninstall removes the runtime.
- **`nodePath` is a legacy field.** `config.json` still requires an absolute `nodePath`, but it is never run; its directory is only the first `PATH` entry given to omp (the current runtime's directory is used when it no longer exists), so omp wrappers that run `env node` keep working.
- **Updates.** Sparkle 2.10.1 checks a signed feed daily (notifications on, automatic installation off by default) with **Update Now**, **Skip This Version**, **Later** and **Turn Off Notifications**. The feed and archive are Ed25519-verified, the installed tree is checked against an authenticated hash, an out-of-bundle watcher restarts the original LaunchAgent, waits for the new app's startup acknowledgment and rolls back otherwise. Automatic restarts wait until the app is idle.
- **Release automation.** A trusted-GitHub-runner `Package` workflow builds and tests a universal DMG with a build-provenance attestation; `release:verify-ci` authenticates it, `release:package -- --ci-run <ID>` signs those exact bytes with the maintainer's local Keychain key and `release:publish` uploads the asset before the signed feed. A keyless `release:audit` checks the committed feed against the public releases, tags and assets, including the bundled Node resources.
- The app is ad-hoc / Ed25519-signed, not Developer ID signed or notarized. Source install (`npm run macos:install`) remains a development fallback.
